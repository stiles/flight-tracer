# Case study: the final recorded departure on January 26, 2020

[Back to README](../../README.md) · [Time-window reference](../cli.md#time-windows)

This example isolates the final departure in the `a9a1ad` archive supplied for Kobe Bryant's final flight. It demonstrates an older trace format, missing leg markers, explicit time selection and optional ground-stop inference. Aircraft identity and accident reconstruction are not independently established by this trace; the exported endpoint is the last received position, not a verified crash location.

## Source and what went wrong

- [ADS-B Exchange trace view](https://globe.adsbexchange.com/?icao=a9a1ad&showTrace=2020-01-26)
- [Historical JSON](https://globe.adsbexchange.com/globe_history/2020/01/26/traces/ad/trace_full_a9a1ad.json)
- 820 source records, each with seven fields: timestamp offset, latitude, longitude, altitude, ground speed, track and flags.
- No new-leg flags. The archive also includes activity before January 26 UTC.

The original parser expected 14 fields. It now retains the seven available values and leaves missing optional fields empty. Plain `--leg latest` still cannot distinguish flights without boundary evidence.

## What the apparent 30-minute stop actually contains

The airborne-only CSV has descending reports ending around **8:37:53 a.m. PST**, at a reported altitude of −150 feet and ground speed of 19.7 knots. Its next airborne report is around **9:06:57 a.m. PST**. A line chart can connect those observations, but the gap does not represent continuous altitude measurements.

The raw JSON provides stronger evidence:

| UTC on January 26 | PST | Report |
|---|---|---|
| 16:38:30.543 | 8:38:30.543 a.m. | Explicit `ground`, 2.7 knots, 33.665391, −117.873988 |
| 17:06:35.843 | 9:06:35.843 a.m. | Explicit `ground`, 33.666787, −117.876577 |
| 17:06:57.443 | 9:06:57.443 a.m. | Numeric altitude 250 feet, 97.9 knots |

The two consecutive ground reports are roughly 28 minutes apart and within one kilometer. They support a possible stop, but do not prove the aircraft remained on the ground throughout the gap. Numeric altitude at or below zero is not used as proof of landing.

## Method 1: select a known time window

```bash
flight-tracer trace --icao a9a1ad --date 2020-01-26 \
  --after 2020-01-26T09:00:00 \
  --before 2020-01-26T10:00:00 \
  --window-timezone America/Los_Angeles \
  --timezone America/Los_Angeles \
  --output data/final-flight-window
```

The equivalent UTC bounds are `--after 2020-01-26T17:00:00Z --before 2020-01-26T18:00:00Z`; no `--window-timezone` is needed when bounds contain offsets. Both ends are inclusive. The display timezone does not change how bounds are interpreted.

The CLI detects available leg boundaries before trimming, then exports only selected observations. It does not interpolate points at the window edges. Add `--keep-ground` if you also want the ground reports before the first airborne record.

## Method 2: infer the departure from ground reports

```bash
flight-tracer trace --icao a9a1ad --date 2020-01-26 \
  --infer-legs --leg latest \
  --timezone America/Los_Angeles \
  --output data/final-flight-inferred
```

For an aircraft without usable leg flags, the optional rule looks for consecutive explicit ground reports at least five minutes apart and within one kilometer, after an airborne report. It starts an inferred leg at the later ground report. Existing archive leg markers take precedence.

On the downloaded archive, this produces three inferred groups and selects group 3. These are conservative groups, not a claim that exactly three flights occurred. Stops without the required ground reports can be missed.

Both methods select the same final airborne observations, approximately **9:06:57–9:45:31 a.m. PST (17:06:57–17:45:31 UTC)**. Inferred output has `leg_detection=inferred_ground_stop` and an explicit map note. The exact fractional timestamps remain in the data.

## Outputs and preservation

Each run includes `trace.csv`, `points.geojson`, `line.geojson`, `summary.json`, `selection.json`, `map.png`, `altitude.png` and `speed.png`. Window and inference suffixes keep these runs separate from an unfiltered archive export.

A preservation bundle is archived at [stilesdata.com/flight_tracer/kobe/](https://stilesdata.com/flight_tracer/kobe/README.md). It includes:

- The complete original JSON, including ground reports excluded from the default plots.
- Both the explicit-window and inferred final-flight outputs, which contain the same 464 observations.
- This explanation, exact reproduction commands (`reproduce.sh`) and provenance metadata (`provenance.json`).
- A snapshot of the rendering code and dependency versions.
- SHA-256 checksums for checking downloaded files (`SHA256SUMS`).
